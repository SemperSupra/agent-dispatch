# agent-dispatch

Minimal, falsifiable experiment for dispatching bounded engineering tasks to cloud coding agents while keeping GitHub as the durable source/result plane.

## MVP hypothesis

A small public control-plane workflow can invoke the Google Jules REST API against an authorized target repository, including a private repository, without copying private source into this repository or keeping a GitHub Actions runner alive while Jules works.

## Hardened Phase 0 flow

The dispatcher is intentionally **not** a generic public Jules relay.

1. A designated operator manually runs **Jules Dispatch**.
2. The public workflow receives only an opaque target ID and an approved task ID.
3. `JULES_TARGETS_JSON` (a GitHub Secret) maps the target ID to a private `owner/repo` and pinned branch.
4. `config/tasks.json` maps the task ID to a committed Markdown task under `tasks/`.
5. `scripts/jules.py` validates both policy decisions before resolving the repository through Jules Sources.
6. The workflow creates the Jules session and exits immediately.
7. Public output deliberately omits private repository names, branches, Jules session IDs/URLs, source IDs, PR metadata, source, patches, and activities.
8. Detailed session/status inspection is performed through a trusted surface such as the Jules UI or a local invocation of the adapter. There is no public secret-bearing status workflow.

The dispatcher deliberately does **not** poll. Jules is the compute plane; GitHub Actions is only the short-lived control plane.

## Required secrets

### `JULES_API_KEY`

A Jules REST API key generated by the operator. Never commit it.

### `JULES_TARGETS_JSON`

A secret JSON mapping from opaque aliases to approved private targets and pinned starting branches:

```json
{
  "phase0": {
    "repository": "OWNER/PRIVATE_REPOSITORY",
    "branch": "PINNED_BRANCH"
  }
}
```

Do not put private repository names in workflow defaults, public repository variables, or task files.

## Approved tasks

Task specifications are public and reviewable. A task must be present under `tasks/` and explicitly registered in `config/tasks.json`. The public workflow does not accept free-form prompt text or arbitrary task paths.

## Security boundary

This repository is a public control plane with private downstream authority. Treat workflow files, `scripts/`, `config/`, and `tasks/` as security-sensitive. See [`SECURITY.md`](SECURITY.md) for the threat model, implemented controls, required GitHub settings, logging policy, and incident response.

Important invariants:

- secret-bearing workflows remain manual-only;
- unknown target/task IDs fail closed;
- only explicitly allowlisted Jules targets may be dispatched;
- public logs must not reveal private target/session/PR metadata;
- no fork/PR/issue-controlled code is executed with Jules credentials;
- `main` should be protected and CODEOWNER review enforced before expanding authority.

## Phase 0 success criterion

Phase 0 succeeds if a manually dispatched workflow can create a Jules session against an approved private target and the resulting private change can be inspected through a trusted surface, without private source or sensitive target/session metadata entering this public control plane.

## Kill / reassess criteria

Stop and reassess before building a generalized dispatcher if the API path cannot reliably target private repositories, requires long-lived Actions polling, exposes private source or target metadata in the public control plane, or needs substantial provider-specific orchestration beyond a thin adapter.

## Current scope

This repository is intentionally **not** a multi-agent platform. No scheduler, database, queue, routing engine, backend registry, automatic retries, or provider abstraction should be added until the narrow experiment is demonstrated.

The Jules REST API is currently alpha, so the adapter should remain small and replaceable.
