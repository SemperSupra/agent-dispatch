## DOE and independent held-out score

One fictional, entirely public-safe evidence collection of 8 observations (7 alpha; 1 beta excluded from model prompt), including duplicate Internet Message-ID across separate unrelated messages, a changed budget, source reacquisition, German denial, Thai approval, missing-ID release item and an off-limits beta-only claim.

Ten independently authored EN/DE/TH questions split into **3 dev** and **7 held-out**. Model sees only its question and the bounded alpha evidence; the gold ID/value and task partition labels are not in the prompt. Two fixed reviewed prompts: `plain` and `evidence-first`. Model chooses `source_id` plus `value` JSON from an explicitly constrained schema (no external API/tool call), temperature 0, seed 19. Both prompts evaluated on dev; candidate selection is by dev exact answer only, tie prefers plain; then both evaluated on held-out to measure a fixed-prompt baseline and selected policy, but held-out results do not influence selection. Count exactly **20 real local model calls**.

The **independent evaluator** compares full expected source ID+exact answer, invalid JSON, wrong source cited, abstention, language, per-sample duration. A result may be bad (e.g. Thai misinterpretation or incorrect time scope) and still qualify as *a genuine measured inference experiment*. The receipt separates `real_model_inference=true` from `semantic_quality_gate` and explicitly sets `automatic_promotion=false`, `model_weights_updated=false`. Quality non-regression policy is **not** automatically promoted to the product. The threshold is 6/7 held-out exact and 0 wrong sources, but this is an exploratory small sample, not meaningful statistical generalization or proof of compliance. Source-context ACL is enforced by the harness excluding beta before the model, so it does **not** measure model-side secrecy.

## Build / deployment / operations

Research use only. `python3 scripts/qualify_mail_qwen_real_cpu.py` inside a fresh public Linux runner downloads a fixed 415 MB model, verifies and extracts the official exact-SHA x64 CPU runtime binary into a disposable temp directory, executes both policy arms under 2 CPU threads and counts source-citation errors. One Python stdout JSON document forms a SHA-pinned origin/metric receipt; the original model weights, build cache and prompts are not uploaded. `gha_workload_request.py` admits only `requests/gha/mail-qwen-real-cpu-v1.json` with a fixed 420-second internal timeout and a parent 8-minute job ceiling. A first install/download/compile/timeout/JSON error is a **failed experiment** and must be recorded, not hidden by substituting fake-model outputs or relaxing the original digest.

Dispose of the entire temporary checkout/build/model/cache after the rep. A production service needs a version-pinned slim OCI artifact and model file with retention rights, hash-verified disk, cold-start and memory profiling, host network egress firewall, corruption/restart/rollback, explicit model routing and secret isolation. This experiment has none of those production guarantees. Runtime/source license checks are source-and-model disclosures only, not a complete transitive SBOM/license/attestation.

## First failure and bounded corrective action

The first exact-head public run [#43839623867](https://github.com/SemperSupra/agent-dispatch/actions/runs/43839623867) passed 26+ source-contract tests but the native model workcell returned FAIL after approximately 186 seconds. The original source build was capped at 175 seconds and had stderr suppressed; no model accuracy result or native independent PASS was produced, and no actual model execution should be claimed. Corrective experiment R6.1 replaces lengthy from-source build with **publisher's official GitHub CPU release tarball** verified against the provider-provided SHA-256 and immutable tag commit. The setup should now fit within existing 8-minute GHA job and 420-second workload caps. The runtime prints only a bounded sanitized first-failure code if a subsequent rep fails; no raw model, compile or network logs are published. Any green result remains a first-party binary deployability and small-model quality measurement, not a from-source reproduction. Do not silently relax the SHA/cost/data gates.

## R6.2 evaluator falsification and corrected scoring

The first provider-native **actual** model measurement completed SUCCESS at [GHA #43841979794](https://github.com/SemperSupra/agent-dispatch/actions/runs/43841979794), source `17294fee198f8dc7954e1423ffd0cb75226470d6`, independent native x64 job `133212694124` and verifier PASS. Actual Qwen 0.5B Q2_K did execute **20 calls** using immutable model/engine digests; artifact `14214100305` ZIP SHA256 `e7c63d7ae514a8b37fde724f3984f2dfaee630a8ac99dbf41fa881bb6f29181a`; receipt `3813d0c0a7211c7bec3b0488671c68da06c7cd56996f021aa6b231cfba8c138f`. The initial scorer reported 0/7 exact and 7 invalid/wrong source references, and selected unmodified `plain`. **Those scores were subsequently INVALIDATED**: source inspection proved the model output regex in `parse_model_json` had two backslashes before literal braces instead of one, making normally structured JSON outputs unmatchable. The real model execution remains valid, but **do not infer intrinsic model reasoning ability from that flawed quality score**.

Corrective code uses an unambiguous literal-brace character class `[{][^{}]{2,400}[}]` and separately falsifies exact JSON object parsing (both property orders, noise, missing/extra fields) without external model calls. R6.2 native receipt now carries both selected and baseline **fictional case metrics**, not original text completions. The **independent provider-bound verifier** separately stores frozen seven-case gold answers, recomputes exact ID/value, valid JSON, abstain, wrong source, and checks that policy selection matches dev-only scores. This prevents arbitrary self-grading by the experiment script, while retaining `automatic_promotion=false` and a quality threshold requiring >=6/7 exact and zero wrong source. Note 7 held-out tasks remain an insufficient sample for general multilingual claims; independent task-family expansion is still required.

Previous repository commits and red receipts remain in GitHub Actions history; no failure is erased, and no real mail or private PST was used. Heavy model downloads must be removed from the routine per-PR CPU matrix after the first requalified case-level result; keep the bounded reviewed fixed request for on-demand future model retests.
