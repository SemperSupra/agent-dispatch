# Temporal R2 — original PostgreSQL 18 database qualification (public synthetic)

Authority: [Mail Evidence private #4](https://github.com/SupraShellScripts/mail-evidence-private/issues/4), reasoning comparison [#39](https://github.com/SupraShellScripts/mail-evidence-private/issues/39). Public-only controlled benchmark, not a migration to PostgreSQL and not a real PST/mail reader.

## Original prior art

The published Docker Official Image `postgres:18.3` is pulled to a disposable standard public Ubuntu 24.04 GitHub-hosted runner. Its **observed content-addressed Docker image ID** is written into the signed-by-provider CI run receipt. The image tag is not a digest pin: `image_digest_pinned=false` and `version_locked=false` are explicit *production hold* flags. The native server runs with **`--network none`**, no published ports and no live account secrets. Only Docker local `exec psql` talks to it; the observed PostgreSQL major version must be 18.

Test the **real** PostgreSQL implementation of `tstzrange` temporal intervals, GiST indexing and new PostgreSQL 18 `UNIQUE (policy_id, valid_period WITHOUT OVERLAPS)` constraint, but **only** for a policy validity window. It would be incorrect to apply exclusive-time constraints to original contradictory source claims, which remain concurrent and immutable. Comparison baseline: previously native SQLite source/claim/assessment tests from PR #860.

## Strict source/claim semantics

Six invented, immutable source occurrences include overlapping exports, repeated original lineage, same Message-ID, planned future assertion, retroactive effective date acquired later, and an isolated beta tenant. Six separate claims attach to original sources with signed polarity, asserted actual/planned modality, exact source text citation, true native `tstzrange` interval and recorded acquisition/observation timestamp. Query uses **two clock arguments**, valid_at and known_at, plus independent source and claim tenant checks. Four-value evidence classification NEITHER/SUPPORTED/REFUTED/BOTH is calculated from source support, not physical truth; claims never overwrite one another.

Eight independent temporal scenario labels are checked by a distinct frozen verifier that hard-codes expected status, exact citation count, independently supported/refuted lineages, tenant isolation and planned-event nonpromotion. PostgreSQL's actual `WITHOUT OVERLAPS` must reject overlapping policy periods. An UPDATE/DELETE trigger on original source, claim, and derived-assessment tables must refuse mutation. Tenant mismatch on a claim must fail at the database trigger. A native container STOP/START must preserve source observations and derived assessments; no source information is moved to public artifacts, only a bounded synthetic receipt and original image ID.

## Cloud execution, limitations, and O&M

One branch-scoped job in the *existing* public typed CPU workflow, conditional only on PR heads beginning `work/mail-temporal-postgres18-`, runs no other portfolio PR workloads and has an eight-minute ceiling. Pull image `postgres:18.3`, execute fixed SQL against isolated PostgreSQL, assert native gap/contradiction and restart, and destroy container via `finally`. Independent verifier binds exact receipt SHA, original GitHub source SHA and GitHub run ID; public artifact retention three days. No new workflow, scheduler, secret, paid model or Sidecar authority.

**Unqualified:** tag-level image is mutable absent a manifest digest pin, official Docker image transitive SBOM not yet reviewed, database long-duration migration, multiwriter concurrency stress, replica/failover, production query latency, cryptographic source custody, real MIME/PST extract, and objective truth of assertions. These remain explicit promotion gates and do not justify keeping this DB running as a service. If Docker pull or SQL error fails, preserve the red run rather than silently substituting SQLite or changing the gold fixture.

## Adversarial first-failure reconciliation (R2 native)

The original exact public [Actions run 44530416371](https://github.com/SemperSupra/agent-dispatch/actions/runs/44530416371) had a **real PostgreSQL schema failure** after the Docker service started; the driver initially redacted native error details. Diagnostic follow-up [run 44531055180](https://github.com/SemperSupra/agent-dispatch/actions/runs/44531055180) identified the failure stage as `PG18_SCHEMA` but no SQLSTATE because the regex was erroneously double-escaped. The next [run 44531295733](https://github.com/SemperSupra/agent-dispatch/actions/runs/44531295733) captured native **SQLSTATE 42704**, consistent with a missing GiST operator class for the `text` equality portion of the PostgreSQL 18 `WITHOUT OVERLAPS` temporal unique key. The correct reuse of upstream PostgreSQL prior art is to first enable the **contrib extension `btree_gist`**. The fixed schema now executes `CREATE EXTENSION IF NOT EXISTS btree_gist;` before declaring a uniqueness exclusion. This is necessary to exercise the real feature; it is **not** a reason to weaken the constraint, create a custom exclusion engine, or exclude contradictory source claims. No native PASS is claimed until the amended exact-head rerun and independent receipt succeed. The experimental tag remains not manifest digest-locked.
