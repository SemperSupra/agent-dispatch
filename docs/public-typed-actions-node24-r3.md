# Typed public CPU R3-C: remove Node20 action runtime warnings with immutable Node24 pins

**Why:** Hosted native Go/SQLite/XTDB research receipts repeatedly showed the known Node.js 20 deprecation warning for pinned `actions/checkout` and `actions/upload-artifact`. This change is narrow CI O&M work, not a new mail product or runtime. Before modification, the existing `.github/workflows/gha-typed-public-cpu.yml` used seven copies of checkout `11d5960a326750d5838078e36cf38b85af677262` and five uploads `ea165f8d65b6e75b540449e92b4886f43607fa02`.

**Source/rights inspection:** Exact official `actions/checkout@v6` public git ref resolves to commit `d23441a48e516b6c34aea4fa41551a30e30af803`, action manifest declares `using: node24`, upstream MIT LICENSE. Exact official `actions/upload-artifact@v6` resolves to `b7c566a772e6b6bfb58ed0dc250532a479d7789f`, manifest `using: node24`, MIT LICENSE. `upload-artifact@v5` still uses node20, which is why simply moving to v5 would **not** close this warning. Both action versions are committed via full-length immutable SHAs, no floating `@main` tags or source redirects.

**Scope:** Change only those twelve action-use locations in the existing typed public CPU workflow. No changes to event triggers, 4 routine CPU matrix profiles, runner labels, authorized secrets, permission grants, input request admission, source SHA, typed receipt, artifact retention, dynamic scripts, public/private data classification or compute budget. Checkout retains `persist-credentials: false`. All execution/verification under the same public pull request and existing provider-bound receipt contract. A new offline test fixes the exact allowed action pins and occurrence counts; a green exact-head native public workflow confirms v6 compatible on standard x64+arm64 GitHub runners and artifact receipts.

**Residual scope:** Other portfolio workflows/repositories may still use Node20 and need their own qualified, least-diff upgrade; this is **not** permission to change their tokens, events, job privileges, repos or runner rights. If v6 breaks the workflow, retain the red first-failure receipt and revert only these substitutions with a new exact-head test; no green claim without real hosted runtime.
