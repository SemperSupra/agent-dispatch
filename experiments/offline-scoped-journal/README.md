# Offline scoped-journal experiment
An isolated, standard-library-only Go candidate for resolving address references against bounded, immutable, producer-declared mapping windows. No target access, capture, actuation, network, or persistent service. Synthetic fixture only; not production code.

`go test -race ./...`, `go vet ./...`, `go run ./cmd/scoped-journal -journal testdata/window.json -at 20 -address 100`.

One CLI JSON result, including the actual input file SHA-256, scope, coordinate, resolution status, evidence digest supplied by the producer and mapping if supported. Exit 2 on invalid input. Unknown scope, coverage gap, unmapped and resolved are distinct. The source digest is a declared reference, not an authenticated proof. A contiguous sealed producer sequence does not prove sensor completeness; status only applies to the declared window. Native identifiers are opaque ASCII, while native names and metadata belong in separate fields. Decimal string uint64 wire values avoid precision loss in JSON consumers. Half-open ranges require representable exclusive ends. Exact map/unmap changes only, strictly increasing local coordinates; no concurrent writers, partial unmaps, causal edges or cross-domain translation. Inputs bounded at 1 MiB / 4096 baseline mappings and events. Build copies input and validates a complete lifecycle; query replays relevant events, so this is not a production-scale index. Never install into the observed target. No private inputs in public CI.

## Evidence binding and explicit scope
Use `-expect-run sample -expect-branch root -expect-space guest-va -expect-producer observer` to assert the complete expected scope rather than accepting the file's scope implicitly. Partial/mismatched scope fails. `-source /path/to/immutable/artifact` optionally verifies the actual source bytes against the declared digest, with a 64 MiB cap; a mismatch refuses the query. The default result explicitly says `source_integrity: declared_only`. A successful check says `digest_matched`, which establishes content integrity but does not authenticate the producer, prove that observations were derived from those bytes, or establish semantic completeness. Use trusted immutable regular-file inputs, not attacker-controlled filesystem paths.
The artifact/range library is a separate primitive: an occurrence within a producer scope has a content digest and size; range validation rejects empty/out-of-bounds ranges without addition overflow. Equal digests do not merge occurrences. No automatic causal inference or integrated range wire format is claimed. Map/unmap denotes mapping lifecycle only, not object birth/death; same generation after remapping is the producer's identity assertion and is not independently validated. Coordinates are local ordered coordinates, not cross-producer time.

## Retained artifact pin verification
`go run ./cmd/artifact-verify -claim claim.json -pin independent.json -source retained.bin` compares the complete scoped occurrence, content digest, and byte size with an independently obtained pin, then verifies bytes under the existing 64 MiB bound. Both reference files use the strict ArtifactRef JSON object (scope with run/branch/space/producer; occurrence; lowercase SHA-256; decimal-string size). Use the built executable for stable exit semantics: 0 = retained_byte_match, 3 = unknown_no_independent_pin (no source read), 2 = refused/invalid/unavailable. JSON status on 0/3; diagnostic on stderr on 2. A pin is a reference supplied by a trusted independent custody path, not by the claimant. The verifier cannot establish that independence or authenticate fresh observations. Identical bytes under distinct scopes or occurrences do not merge. A match does not establish mapping correctness, sensor completeness, or causality. Use trusted immutable regular-file paths. The existing journal query remains separate; no implicit promotion of its evidence status.

## Native reported-address correspondence
`ResolveNativeELF64` is an offline library entrypoint, not an execution observer. It binds the selected full pointer record (`label=0x...`) and a contiguous selected range of complete Linux proc-map lines to one independently pinned retained capture, checks an independently pinned candidate image, and translates file offset into an executable PT_LOAD virtual address. Supported: bounded ELF64 LE x86-64 ET_DYN/ET_EXEC, nonoverlapping sorted mappings, file-backed executable extents. Explicit module path association comes from caller context, not procfs file identity proof; a candidate correspondence is not an executed PC, runtime memory-byte match, authenticated module load, mapping completeness, or causal claim. Missing pin/mapping/file backing is UNKNOWN; malformed or contradictory data is refused. Capture limit 1 MiB; existing image limit 64 MiB. No target access. Native fixture qualification: `NATIVE_ELF_TEST=1 go test -count=1 -race -v -run '^TestNativeELF$' .`.

## Read-only native correspondence CLI
Build `go build ./cmd/native-correspondence` and discover flags with `native-correspondence -help`.
The request is a strict `native-correspondence/v1` JSON object with `schema`, `expected_scope`, `pointer`, `maps`, `label`, `module_path`, and `image`. The two ranges use `artifact` (ArtifactRef), `offset`, `length`; the image is an ArtifactRef. Coordinates remain decimal strings; paths must be valid UTF-8 without replacement characters. Example invocation:
`native-correspondence -query request.json -query-sha256 EXPECTED_SHA256 -capture-pin capture-pin.json -image-pin image-pin.json -capture capture.txt -image candidate.elf`.
The request hash and both artifact references must come from separately trusted custody/context. The verifier cannot prove their independence. Without a query pin or either artifact pin, return UNKNOWN (exit 3, no source bytes opened); contradictory supplied pins, malformed input or source mismatch refuse (exit 2, no positive stdout). Candidate correspondence is exit 0. Missing mapping/backing is exit 3. Results include the request digest, selection and artifact integrity, explicit evidence ceiling, path-image association and selected-lines-only coverage. Location is present only on candidate correspondence; all numeric fields are decimal strings. Optional expected address, ELF virtual address and complete map base/end check caller-supplied coordinates without upgrading the evidence class. No executed-PC, loaded-byte, authenticated producer, global completeness or causal proof. No target control, hidden network service or additional runtime instrumentation. Use immutable trusted regular-file paths; hostile filesystem races are out of scope. Standard-library Go, independent Python process oracle in testdata/native_query_oracle.py.

## Bounded cross-occurrence byte-range relation
Build `go build ./cmd/range-relation` and discover flags with `range-relation -help`. Request `range-relation/v1` has exactly `schema`, `left`, `right`. Each is an EvidenceRange (ArtifactRef, decimal string offset/length). Compare equal-length nonempty ranges up to 1 MiB each, against separately supplied exact query digest and artifact occurrence pins. Example: `range-relation -query request.json -query-sha256 EXPECTED -left-pin l.json -right-pin r.json -left a.bin -right b.bin`. Exit 0 means only the selected byte relation was established; result distinguishes equal/different and optional first difference relative to selected range, same vs distinct declared occurrence, shared declared occurrence vs unknown dependency, and always unknown causality. No raw selected bytes in output. UNKNOWN exit 3 on missing pin without reading source; REFUSE exit 2 on invalid/contradictory evidence. Same occurrence with conflicting digest/size is refused. Separate artifact scopes and equal content do not prove source independence, time alignment or causal identity. No global equivalence from equal subranges. Entire bounded sources (up to 64 MiB each) are streamed and hashed on each successful comparison; only selected bytes are retained. `selected_bytes` is per-side logical range size and `verified_source_bytes` is the combined source bytes hashed, not physical I/O. No caching yet, no target instrumentation, no causal graph or authority. Trusted immutable files and independently sourced pins are caller prerequisites.

## Verify once, compare many (bounded batch)
The existing `range-relation batch` subcommand accepts a strict `range-relation-batch/v1` request: `schema`, `questions` (each with unique `id`, `left`, `right` EvidenceRange). Use `range-relation batch -help` and `range-relation batch -query questions.json -query-sha256 EXPECTED -sources pins.json`. The separately trusted source manifest is `range-relation-sources/v1` with `sources` (each has `artifact` ArtifactRef and `path` trusted immutable regular file). Pins and request hash must be obtained independently of claimant. All questions and all supplied pins are validated before sources open; absent required pin returns UNKNOWN, contradictory/extra/duplicate pin refuses. All-or-nothing: any failed source hash/size/read/close yields no partial answers. Each declared occurrence is opened and hashed exactly once per successful batch. Identical content in different occurrences is not coalesced. Exact duplicate selected ranges share storage; overlapping nonidentical ranges count separately. Limits: 32 questions, 8 occurrences, 8 MiB retained selections, 128 MiB total source bytes, existing 1 MiB per-range/64 MiB per-source limits. Output counts combined logical selected bytes, retained distinct range bytes, verified source bytes, and counterfactual separate-query source bytes (not measured physical I/O); per-question results preserve content/occurrence/dependency and global causal UNKNOWN. All buffers are call-local; no persistent cache or reuse across invocations. No proof of independent producer, global equality, history or causality. Use trusted finite immutable files; no hostile filesystem or service admission guarantee. Exit0 compared, 3 UNKNOWN, 2 refusal; JSON only on 0/3.
