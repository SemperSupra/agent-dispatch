# R59 — public two-writer lost-update negative proof

**Red-team follow-up to R56**, not a feature implementation. R56 established a one-pointer commit process-crash capability in single-writer synthetic tests. This public-safe experiment proves the missing concurrency constraint: two independent writers both observe the old generation, independently stage valid complete generations, and each successfully atomically replaces the one current-generation pointer. An explicit two-writer barrier forces A to commit first and B to commit second. A's durable generation remains but becomes **unreferenced and logically lost**; the final pointer sees only B. Three deterministic repetitions per native AMD64/ARM64 public GHA. This is a successful **negative witness**, not a correct multiwriter transaction.

Each run uses synthetic bytes under disposable scratch, an isolated network namespace, uid/gid65534, zero effective caps and no dependencies. The known lost update demonstrates why an R56-style design would require a single-writer lock or compare-and-swap and reader/GC ownership before private Winnow adoption. It does not prove power-loss recovery, external data storage, actual product integration, source rights, or release. No credentials, private repository content, Instagram or production artifacts are used.
