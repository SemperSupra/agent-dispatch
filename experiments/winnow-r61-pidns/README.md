# R61 — PID namespace init teardown against detached session

R58's public negative witness proved a `setsid` descendant can survive termination of its spawner's process group. This independently tests a **narrower whole-PID-namespace teardown** capability on disposable Linux GitHub-hosted AMD64/ARM64 runner nodes: a root-only runner observer starts a new mount, PID and route-less net namespace with `unshare --pid --fork --mount-proc`; PID namespace init and its detached session child run uid/gid 65534, zero caps. After confirming both as host-visible process members, the runner observer kills **only the isolated PID namespace init** and checks that no live namespace process remains. Three repetitions, offline synthetic `sleep` only.

The host-side observer temporarily runs root inside the disposable public GitHub runner to inspect `/proc`, identify the PID-namespace init's host PID, and enforce last-chance cleanup. Never run this on persistent hosts or on unapproved workloads. The test explicitly rejects an environment without the expected namespace setup; no silent fallback to a process-group-only supervisor. No private Winnow code, real downloader, Instagram, credentials or data.

**Qualification limit:** This is a Linux OS **primitive** demonstration, not a fully secure container, resource quotas, an immutable service runtime, private `Backend` or toolchain integration, actual extractor behavior, BigMac/macOS/TrueNAS/Windows parity, sandbox escape resistance, durable data store, release or source rights. Product promotion requires per-download PID/mount namespace or equivalent isolation, cgroup v2 CPU/memory/I/O budget, fixture/cleanup tests, proper seccomp and mount/uid threat model, independent reviewer and exact-head private CI.
