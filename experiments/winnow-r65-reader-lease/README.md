# R65 — shared reader leases exclude old-generation GC on one local filesystem

R56's one-pointer batch commit was safe only as a **synthetic single-writer process-crash concept**; R59 showed lost updates from two writers; R62 demonstrated `fcntl.flock` serialization on a local Linux filesystem. R65 tests the next independent concern: **do not delete an old immutable generation while any reader still holds its snapshot**.

Two unprivileged synthetic readers acquire shared `flock` leases on the generation lease file, then a separate garbage collector attempts an exclusive lock. The test checks that GC cannot remove retired bytes while two readers hold their leases, nor after only reader A exits. In the crash case, A is deliberately killed to prove the kernel releases that lease while B's remaining lease still prevents deletion. After the final reader releases, the collector removes only the retired generation while the current one stays byte-for-byte identical. Three repetitions each of normal and crashed-reader mode, on independent disposable Ubuntu AMD64/ARM64 public GHA. No external dependencies or host installs.

This primitive does **not** establish cross-host reader leases, distributed/remote durable storage, power-loss crash consistency, snapshot correctness across noncooperating readers, symlink/TOCTOU resistance, or private Winnow application integration. No real extractor, Instagram, credentials, source media or private code. A PASS here is not a replacement for explicit product `RECOVERY_ATOMICITY_NOT_IMPLEMENTED` and does not authorize release.
