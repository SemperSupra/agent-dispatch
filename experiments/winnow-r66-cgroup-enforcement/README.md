# R66 — actual cgroup v2 PID and memory enforcement on disposable GHA

R64 showed that disposable GitHub-hosted AMD64 and ARM64 Ubuntu runners can **create empty cgroups and configure** CPU, memory and PID limits. It did not execute a limited workload. R66 separately tests **kernel-enforced denial**, without private Winnow source or media.

A root *supervisor inside a disposable runner and isolated route-less network namespace* creates an owned child cgroup per test, writes either `pids.max=4` or `memory.max=67108864`, launches a synthetic worker that moves itself into the cgroup, **drops to uid/gid65534**, then triggers limits. PID case must get Linux `EAGAIN` on the fourth spawned `/bin/sleep` (one worker + three children allowed), plus `pids.events max >= 1`. Memory case attempts 512 MiB of touched memory, must terminate with SIGKILL and `memory.events oom_kill >= 1`. The supervisor independently reaps the cgroup, removes only its owned cgroup directory and reports events. Three repetitions per case per architecture. Strict failure if the kernel behavior or cleanup is not observed.

This intentionally tests **two** controls; CPU throttling and I/O device quotas remain NOT_RUN. It does **not** prove a complete sandbox, systemd/OCI orchestration, seccomp, namespace escape resistance, actual vendor process admission, BigMac/macOS, Windows or TrueNAS capabilities, product integration, source rights or release. No host installation or parent cgroup configuration. Must not run this on persistent hosts; only disposable public-safe runners. DLE preserves first failures.
