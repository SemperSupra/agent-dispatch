# R71 — same-run cgroup memory/swap differential, public synthetic

R68 found an architecture split: ARM64 killed 192MiB synthetic anonymous `mmap` under `memory.max=64MiB`, AMD64 completed with no OOM despite a 64MiB peak. R70 separately added `memory.swap.max=0` and observed SIGKILL plus OOM events on **both** architectures. Because R68/R70 ran on different ephemeral runners, attributing the change to swap is a plausible but not yet fully isolated inference.

R71 runs a **within-one-run controlled comparison**, in newly created child cgroups only, on disposable GitHub-hosted Linux AMD64 and ARM64. For each of **3 repetitions**, it tests a 16MiB positive control and a 192MiB negative case at identical `memory.max=64MiB`, first with `memory.swap.max=max` (available), then `memory.swap.max=0` (off). The negative OFF case **must** be killed by kernel SIGKILL with `memory.events oom_kill >= 1`. The AVAILABLE case may either be killed, or finish only if `memory.swap.peak > 0` provides direct evidence that swap-backed completion occurred. Output captures actual outcomes and memory/swap peak. No claims are made in advance about which behavior each runner will display.

A root supervisor runs solely on disposable public GHA runners in route-less net namespace; unprivileged synthetic workers drop uid/gid65534 after joining a scoped empty cgroup. No parent cgroup/global swap changes, persistent host work, private Winnow source/media, real downloader, credentials or live requests. This does not qualify a production sandbox, CPU/I/O quotas, process-tree lifecycle, target platform or source rights. Draft/unmerged.
