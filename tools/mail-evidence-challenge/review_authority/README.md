# Root-pinned review lifecycle reference

A separate authority verifies a signed, sequence- and predecessor-bound journal against an externally configured root key and exact trusted head. Each tenant/policy/catalog scope has distinct custody. The journal contains grants, prospective revocations, exact review-payload registrations and seals. Reviewer identities and keys cannot be reused; the root key cannot be a reviewer key. Registration checks the reviewer grant at the root-recorded time. A sealed UTC-second interval cannot be retroactively extended. Replay validates the complete chain and derives an as-of inventory from all registered source reviews and revisions whose endpoints are visible, rejecting missing coverage. Expired or revoked keys cannot register new reviews; previously registered reviews remain eligible for historical verification. Key compromise and retroactive quarantine require a separate explicit policy.

This is a bounded public synthetic research primitive, not a deployed catalog, timestamp authority, production PKI, durable database, key distribution, or proof that a root operator has catalogued or interpreted every source correctly. The caller must independently provision the current head/root, and a root capable of issuing a dishonest alternate head is outside this verifier's threat model. The journal records payload digests only; the subsequent pipeline must verify actual reviewer signatures and match identity, recorded clock, digest and ordered source endpoints. One immutable review per source/revision ID; versioned replacement/retirement is not implemented. Strict UTC seconds and no backdating are intentional conservative reference policies. Tests use publicly known synthetic keys and serialization replay, not production secrets or crash durability. No mail or private corpus, no model inference, no new scheduler or recurring CI work.
